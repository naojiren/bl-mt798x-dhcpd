# CT3003 NAND / eMMC 源码

## 构建

NAND 多分区修复版（fix4）：

```sh
make BOARD=cetron_ct3003 VERSION=2025 MULTI_LAYOUT=1 FIXED_MTDPARTS=1
```

eMMC 改装版：

```sh
make BOARD=cetron_ct3003-emmc VERSION=2025 MULTI_LAYOUT=0
```

NAND 与 eMMC 使用各自的设备树和配置。eMMC 使用 DDR4、MMC 环境与 GPT；其引脚及分区需由对应改装硬件确认。以上源码已交叉编译，尚未完成本次版本的实机启动、刷写与断电保存验证。

## NAND 布局

| 布局 | MTD 分区 |
| --- | --- |
| 大分区（113152k) | `nmbm0:1024k(bl2),512k(u-boot-env),1024k(art),1024k(Factory),2048k(fip),113152k(ubi)` |
| 原厂小分区 | `nmbm0:1024k(bl2),512k(u-boot-env),1024k(art),1024k(Factory),2048k(fip),32768k(ubi),32768k(ubi_backup),4096k(Config_backup)` |

修复内容：

- 先校验固件及大小，再擦除原厂小分区的完整 ubi 区域；大分区 FIT 更新同样先清除完整 ubi，写入后重新挂载检查。
- 原始 UBI 镜像按擦除块跳过末尾全 0xff 页，仍验证完整镜像，防止后续 UBIFS 写入对已编程空白页再次编程。
- 原厂 UBI 更新重建 rootfs_data，初始化独立 Config_backup/conf，校验显式 UBI 参数并修正整数解析。
- 成功后保存布局环境；保存、擦除、写入及重新挂载失败均不报告成功。
- 对已确认支持 NMBM 的 CT3003 ubootmod 大分区内核，在 FIT 校验后补齐内存设备树的 NMBM 属性，并将 ubi 限定为 0x580000 + 0x6e80000。保留 MAC、校准数据、fitblk/rootdisk 引用；其他机型及原厂小分区设备树不变。
- FIT 模式先探测实际存在的卷，避免不存在的 kernel/rootfs 卷被当作异常读取。
- 合并保留 master 已有的 Oray X1 Pro ubi_0 完整分区擦除恢复逻辑。

NAND 板级硬件定义参照用户提供的 c775c770 U-Boot DTB，修复源码基于 18fa706818bcbbe7255c74c88922898ef7adc022 并合入当前 master。普通构建脚本会重新编译 ATF；已交付的本地 fix4 FIP 使用参考固件的原 BL31，因此二者不保证逐字节相同。

## 主机验证

测试提取实际 C 源码，使用 ASan/UBSan、实际 libfdt 和 NAND 编程模型。底层闪存/UBI 初始化为模拟，不代表实机验证。

准备外部样本目录：

```text
fixtures/
  evidence/1.bin
  evidence/2、CT3003new.bin
  evidence/large-matched.itb
  kernel-1.dtb
  stock-kernel-dtb-0x32d588.bin
  sysupgrade-kernel-dtb-0x4fb1cc.bin
  tests/
```

`large-matched.itb` 为 ImmortalWrt 25.12.2 CT3003 ubootmod sysupgrade，SHA256 为 `f83509120ec92adf0627882f67ec77eb77bf21cc1338594f7367cd84e7c3f58b`。三份 DTB 分别提取自上述大分区固件、原厂固件与小分区 sysupgrade。

```sh
export CT3003_TEST_FIXTURES=/absolute/path/to/fixtures
python3 tools/ct3003/test_flash_paths.py
python3 tools/ct3003/test_ubi_trimffs.py
python3 tools/ct3003/test_linux_fdt.py
```

需安装 gcc、zlib 开发库、Python 3。固件样本不随源码发布。原 44 类修复测试加上 3 类 Oray 合并回归测试，共 47 类。
